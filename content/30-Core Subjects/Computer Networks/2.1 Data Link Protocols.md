### Data Link Layer Protocols

Data link layer protocols operate in the data link layer of the [OSI model](0.2%20OSI%20Model.md), which sits just above the [physical layer](1.%20Physical%20Layer.md). These protocols are responsible for managing data transmission across network links, ensuring reliable and efficient communication. The main services provided by data link layer protocols include framing, flow control, error detection/correction, and multipoint transmission management.

#### Key Functions of Data Link Layer Protocols

1. **[2. Data Link Layer](2.%20Data%20Link%20Layer.md#Frame%20Fields|Framing)**:
   - Converts a stream of bits from the physical layer into data frames, with sizes ranging from a few hundred to a few thousand bytes.
   - Each frame includes headers with the sender and receiver's addresses for accurate data delivery.

2. **[2. Data Link Layer](2.%20Data%20Link%20Layer.md#Core%20Responsibilities%20of%20the%20Data%20Link%20Layer|Flow%20Control)**:
   - Regulates data flow to ensure a fast sender does not overwhelm a slower receiver, preventing data loss.

3. **[Error Detection and Correction](2.4%20Introduction%20to%20Error%20detection%20and%20Correction.md)**:
   - Detects and corrects corrupted or lost frames during transmission, ensuring data integrity.

4. **Multipoint Transmission**:
   - Controls access to shared channels in broadcast networks, such as LANs.

#### Common Data Link Layer Protocols

![450](00-Attachments/21.1 Data Link Protocols.png)

1. **Synchronous Data Link Protocol (SDLC)**:
   - Developed by IBM in 1975, SDLC supports multipoint links, error recovery, and error correction.
   - Used in Systems Network Architecture (SNA) to connect remote devices to mainframes in both point-to-point and point-to-multipoint setups.
   - Ensures proper data flow between network points.

2. **High-Level Data Link Control (HDLC)**:
   - Based on SDLC and created by ISO in 1979, HDLC is a bit-oriented protocol suitable for both point-to-point and multipoint communication.
   - Provides both unreliable (best-effort) and reliable service, making it a standard for wide area network (WAN) communication.

3. **Serial Line Internet Protocol (SLIP)**:
   - An older protocol that adds a framing byte at the end of IP packets for transmission over dial-up links between ISPs and home users.
   - SLIP does not support error detection or correction and is primarily used with serial ports.

4. **Point-to-Point Protocol (PPP)**:
   - A versatile protocol that functions like SLIP but with additional support for multiple protocols, error detection, and framing.
   - Widely used for dial-up and broadband connections, PPP includes **Link Control Protocol (LCP)** and **Network Control Protocol (NCP)** for link management and network-layer protocol negotiation.

5. **Link Control Protocol (LCP)**:
   - A subprotocol of PPP that establishes, configures, and terminates data links, providing error detection and configuration options for link setup.

6. **Link Access Procedure (LAP)**:
   - A set of data link protocols derived from SDLC, LAP protocols manage framing and data transfer over point-to-point links, with three main types:
     - **LAPB (Link Access Procedure Balanced)**, **LAPD (D-Channel)**, and **LAPF (Frame-Mode Bearer Services)**.

7. **Network Control Protocol (NCP)**:
   - Originally developed for ARPANET, NCP allows remote access and file transfers, forming part of PPP’s protocol suite.
   - NCP was eventually replaced by TCP/IP in the 1980s.

These protocols collectively enable reliable, organized, and efficient data transmission across various types of network links, from dial-up connections to modern broadband networks.
