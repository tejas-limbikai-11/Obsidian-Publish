# TCP / IP Model

### TCP/IP Model Overview

The **TCP/IP model** (Transmission Control Protocol/Internet Protocol) is a set of protocols that defines how data is transmitted across networks and the internet. Its primary role is to transfer data reliably and accurately from one device to another. TCP/IP ensures that data sent from a sender is received exactly as it was sent, without corruption or loss, by dividing it into packets. These packets are recombined at the receiving end to maintain the integrity of the original data.

### How TCP/IP Works

1. **Data Division**: At the sender’s end, TCP/IP breaks data into packets. Each packet is independently routed through the network to the destination.
2. **Data Reconstruction**: At the receiver’s end, these packets are reassembled in the correct order to form the original data.
3. **Real-World Flexibility**: The TCP/IP model is adaptable to various physical media and network technologies, making it ideal for the internet. Unlike other models, it does not rigidly specify physical layer requirements.

### Layers of the TCP/IP Model

The TCP/IP model operates on a **4-layer structure** that processes data as it moves through each layer:

1. **Application Layer**: Provides application services for data exchange (e.g., HTTP for web pages).
2. **Transport Layer** (TCP/UDP): Manages data segmentation, error checking, and data flow control.
3. **Network/Internet Layer** (IP): Routes packets across networks, ensuring they reach the correct destination.
4. **Network Access Layer**: Controls the physical transmission of data over network interfaces.

### TCP/IP Communication Process

In TCP/IP communication, data encapsulation and de-encapsulation help manage data transfer:

- **Encapsulation**:
  - The application layer (e.g., HTTP) sends data to the transport layer, which segments it.
  - IP adds source and destination addresses to create an IP packet.
  - Ethernet information is added, forming an Ethernet frame.
  - This frame is sent through routers, where each router updates link-layer information before forwarding.

![500](00-Attachments/0.3 TCP IP Model-1.png)

- **De-encapsulation**:
  - The receiver processes and removes headers in reverse order:
    1. Ethernet header
    2. IP header
    3. Transport layer header
    4. Application layer (HTTP) information
  - Finally, data is sent to the receiving application.

![550](00-Attachments/0.3 TCP IP Model-2.png)

### Key TCP/IP Concepts

- **Encapsulation**: Packaging data with each layer’s protocol headers as it moves down the layers from sender to receiver.
- **De-encapsulation**: Stripping off headers in reverse as data moves up the layers on the receiving end.

TCP/IP’s efficient, adaptable, and layered structure makes it the backbone of the internet, supporting reliable, end-to-end communication between networks and devices.

### TCP/IP Model Layers and Associated Protocols

![700](00-Attachments/0.3 TCP IP Model.png)

1. **Application Layer**:
   - This layer provides various services directly to the user and includes protocols used for specific tasks.
   - **Protocols**:
     - **DNS** (Domain Name System) for resolving domain names.
     - **BOOTP** and **DHCP** for host configuration, including IP address assignment.
     - **SMTP, POP, IMAP** for email services.
     - **FTP, TFTP** for file transfers.
     - **HTTP** for web browsing.
   - This layer combines functions of the Application, Presentation, and Session layers in the OSI model.

2. **Transport Layer**:
   - Manages data transfer between devices, providing error-checking, data flow control, and reliability.
   - **Protocols**:
     - **TCP** (Transmission Control Protocol) for reliable data transfer with acknowledgment and retransmission.
     - **UDP** (User Datagram Protocol) for faster, connectionless data transfer where speed is prioritized over reliability.

3. **Internet Layer**:
   - Responsible for logical addressing and routing to ensure data packets reach the correct destination across networks.
   - **Protocols**:
     - **IP** (Internet Protocol) for addressing and routing.
     - **NAT** (Network Address Translation) for modifying IP address information in packet headers.
     - **ICMP** (Internet Control Message Protocol) for sending error and control messages.
     - **Routing Protocols**:
       - **OSPF** (Open Shortest Path First) and **EIGRP** (Enhanced Interior Gateway Routing Protocol) for dynamic routing.

4. **Network Access Layer**:
   - Handles physical network functions and data link control, which involves hardware addressing and interfacing with the physical medium.
   - **Protocols/Technologies**:
     - **ARP** (Address Resolution Protocol) for mapping IP addresses to physical MAC addresses.
     - **PPP** (Point-to-Point Protocol) for establishing direct connections between network nodes.
     - **Ethernet** for local network data transmission.
     - **Interface Drivers** for communication with network hardware.

### Comparison to OSI Model

- The **TCP/IP model** has fewer layers (4) by combining the roles of certain OSI layers:
  - The **Application Layer** in TCP/IP encompasses the OSI's Application, Presentation, and Session layers.
  - The **Network Access Layer** in TCP/IP combines OSI's Data Link and Physical layers.

## Difference between TCP/IP and OSI Model

| **TCP/IP**                                                                                                             | **OSI**                                                                                                  |
| ---------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| TCP refers to Transmission Control Protocol.                                                                           | OSI refers to Open Systems Interconnection.                                                              |
| TCP/IP uses both the session and presentation layer in the application layer itself.                                   | OSI uses different session and presentation layers.                                                      |
| TCP/IP follows connectionless a horizontal approach.                                                                   | OSI follows a vertical approach.                                                                         |
| The Transport layer in TCP/IP does not provide assurance delivery of packets.                                          | In the OSI model, the transport layer provides assurance delivery of packets.                            |
| Protocols cannot be replaced easily in TCP/IP model.                                                                   | While in the OSI model, Protocols are better covered and are easy to replace with the technology change. |
| TCP/IP model network layer only provides connectionless (IP) services. The transport layer (TCP) provides connections. | Connectionless and connection-oriented services are provided by the network layer in the OSI model.      |
