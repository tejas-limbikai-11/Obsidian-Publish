# Data Link Layer (DLL)

The **Data Link Layer** (DLL) in the OSI model is responsible for **node-to-node** or **hop-to-hop delivery** within the same network. It ensures data communication between neighboring network nodes. The DLL enables **communication within a network** without requiring higher layers.

#### Core Responsibilities of the Data Link Layer:

1. **Flow Control**
   - Manages the rate of data transmission to prevent the receiver from becoming overwhelmed.
   - Techniques include:
     - **[Stop and Wait](2.2.1%20Stop%20and%20Wait%20Protocol.md)**: Ensures each frame is acknowledged before the next one is sent.
     - **[Go-Back-N](2.2.2%20Go-Back-N%20Protocol.md)**: Allows a window of frames to be sent but requires retransmission of unacknowledged frames from the last acknowledged one.
     - **[Selective Repeat](2.2.3%20Selective%20Repeat%20Protocol.md)**: Only retransmits the specific frames that were not acknowledged.

2. **Access Control**
   - Controls data transmission among multiple devices on a shared communication channel to prevent data collisions.
   - Techniques include:
     - **CSMA/CD (Carrier Sense Multiple Access with Collision Detection)**: Nodes sense the channel and detect collisions, halting transmission and retrying after a delay.
     - **CSMA/CA (Carrier Sense Multiple Access with Collision Avoidance)**: Attempts to avoid collisions by waiting for an idle channel before transmitting.
     - **ALOHA**: Basic access method where nodes send data whenever they have it, with retransmission after collision.
     - **Token Passing**: Allows nodes to transmit data only when they possess a unique token.

3. **Error Control**
   - Detects and possibly corrects errors in transmitted data.
   - Techniques include:
     - **[CRC (Cyclic Redundancy Check)](2.4.3%20Cyclic%20Redundancy%20Check%20\(CRC\).md)**: Adds a checksum to each frame for error detection.
     - **[Checksum](2.4.2%20Checksum.md)**: Adds a computed value to detect errors.
     - **[Parity Check](2.4.1%20Simple%20Bit%20Parity%20&%202D%20Parity%20Check.md)**: Uses parity bits to detect single-bit errors.

4. **Frames**
   - The DLL receives packets from the network layer and divides them into frames for transmission to the physical layer. Frames enhance reliability and contain specific fields that provide structure to the data.

#### Frame Fields

![](https://ccna-200-301.online/wp-content/uploads/2020/04/Frame-fields-Network.png)

A frame is composed of the following fields:

1. **Header**:
   - Marks the beginning of the frame and includes details for addressing, type, and control.

2. **Packet (Data)**:
   - Contains the payload or actual data that is passed from the network layer.

3. **Trailer**:
   - Provides the **error detection** information and indicates the end of the frame.

Detailed fields in a typical frame structure include:

- **Frame Start**: Signals the start of the frame.
- **Addressing**: Specifies the sender and receiver addresses for frame identification.
- **Type**: Indicates the type of data or protocol.
- **Control**: Manages the data flow and acknowledgment of frames.
- **Data**: Holds the packet or payload from the network layer.
- **Error Detection**: Includes error-checking data such as CRC to detect any transmission errors.
- **Frame Stop**: Marks the end of the frame, confirming the completion of data transmission.
