### Address Resolution Protocol (ARP)

The **Address Resolution Protocol (ARP)** is a network protocol that maps an IP address to a device's physical (MAC) address on a Local Area Network (LAN). ARP allows devices to find the hardware (MAC) address of other devices on the same network when only the IP address is known.

While **MAC addresses** are **fixed**, **IP addresses** are constantly **updated**.

![](https://images.javatpoint.com/tutorial/computer-network/images/arp.png)

#### Key Purpose of ARP

- Converts a **32-bit IP address** ([network layer](3.%20Network%20Layer.md)) to a **48-bit [2.6  Media Access Control (MAC) Layer](2.6%20%20Media%20Access%20Control%20\(MAC\)%20Layer.md#MAC%20Address|MAC%20address)** ([data link layer](2.%20Data%20Link%20Layer.md)).
- This mapping is essential because the IP and MAC address formats differ, making translation necessary for devices to communicate in a network.

### How ARP Works

1. **Device Joins Network**: A device joining a LAN receives a unique IP address for identification and communication.
2. **Data Packet Destination**: When a data packet reaches a network gateway, ARP finds the MAC address associated with the destination IP.
3. **ARP Cache**: Every device maintains an ARP cache, which stores recently mapped IP-to-MAC addresses to avoid repeated requests.
4. **Cache Lookup**: If a MAC address is found in the ARP cache, the device uses it for data transmission.
5. **ARP Request**: If the IP-to-MAC mapping is not in the cache, ARP broadcasts a request to the network to find the MAC address corresponding to the IP address.
6. **ARP Response**: The device with the matching IP responds with its MAC address, which is then stored in the ARP cache for future use.

#### ARP Cache and Its Role

- **Dynamic ARP Cache**: The ARP cache is updated regularly and contains temporary entries. Unused addresses are periodically purged to free up space.
- **Static ARP Cache**: Users can configure static entries for devices with fixed IP and MAC addresses.
- **Cache Purging**: To protect against IP spoofing and cyberattacks, stale entries are removed from the ARP cache.

#### Example Scenario

Suppose Device A wants to communicate with Device B on the same network:

- Device A already knows Device B's IP address but not its MAC address.
- Device A first checks its ARP cache. If the MAC address is available, Device A uses it for direct communication.
- If the MAC address is missing, Device A sends an ARP broadcast to the network. Device B replies with its MAC address, which Device A saves in its ARP cache.

### Types of ARP

ARP variations handle different scenarios and requirements on a network.

1. **Reverse ARP (RARP)**: Used by devices that do not know their own IP address. Devices request their IP address by broadcasting their MAC address to the network's ARP table.

2. **Proxy ARP**: When a device on one network segment needs to communicate with a device on another segment, a proxy device on the local network responds to ARP requests for IP addresses not within the local segment. The proxy provides its MAC address to route data to the intended recipient.

3. **Inverse ARP (IARP)**: The reverse of ARP, it uses a known MAC address to find the IP address associated with it. IARP is commonly used in networks like ATM (Asynchronous Transfer Mode) to resolve IP addresses from Layer 2 (MAC) addresses.

---

### Summary

**ARP** plays a crucial role in connecting IP addresses to physical MAC addresses, making device communication possible within a local network. By maintaining an ARP cache, the protocol reduces redundant requests and helps in efficient data transmission. Through specialized types like RARP, Proxy ARP, and Inverse ARP, ARP supports varied network configurations, improving flexibility and interoperability across complex networks.
