# Classful IP Addressing

#### Why Classful IP Addressing Was Needed

- Originally, IP addresses were split into two parts: a Network ID (NID) of 8 bits and a Host ID (HID) of 24 bits. This configuration created only 256 possible networks but allowed each network to have around 16 million hosts.
- Consequently, even a small organization, if allocated a network, would get 16 million IP addresses—wasting a large portion of them. Classful addressing allowed networks to be divided into categories, each with different NID and HID sizes, making it more practical for networks of various sizes.

### Dotted Decimal Notation

To make IP addresses more readable, IP addresses are represented in dotted decimal notation. This format divides the 32-bit IP address into four 8-bit segments (or "octets"), each separated by a dot (e.g., 192.168.1.1).

![Dotted Decimal Notation](https://media.geeksforgeeks.org/wp-content/cdn-uploads/IP_addressing_1.jpg)

Some rules for dotted decimal notation:

- The value of any segment (byte) is between 0 and 255 (both included).
- Leading zeros are not allowed in any segment (e.g., "054" is incorrect, while "54" is correct).

### Class A in IP Addressing

**Network ID** = 8 bits
**Host ID** = 24 bits

![Class A](https://media.geeksforgeeks.org/wp-content/cdn-uploads/IP_addressing_4.jpg)

- IP addresses belonging to class A ranges from 0.0.0.0 – 127.255.255.255.

- The IP addresses are defined by the first octet’s highest bit being **0**. This means the first octet ranges from **0 to 127**.

- Class A IP addresses are identified by the **first bit of the first octet**, which is set to 0.

- **No. of IP Addresses** = 2^31

- **No. of Networks** = 2^7 - 2 = 128 - 2 = 126
  - Two addresses are reserved: **0.0.0.0** (used as the "unspecified address") and **127.0.0.0** (reserved for loopback testing).

- **No. of Hosts** = 2^24 - 2
  - Two Addresses are reserved:
  1. **Network Address** (Reserved Host Address)
     - The **first address in the IP range** (i.e., `x.0.0.0` for any network in Class A) represents the **network address**.
     - This address is used to identify the network itself and **cannot be assigned to any individual device**. It’s crucial because routers and devices use this address to refer to the entire network rather than any single host within it.
     - Ex. `64.0.0.0`
  2. **Broadcast Address** (Reserved Host Address)
     - The **last address in the IP range** (i.e., `x.255.255.255` for any Class A network) is reserved as the **broadcast address**.
     - This address is used to send messages to **all devices** within the network simultaneously. When a device sends data to the broadcast address, every device in that network receives it.
     - Ex. `64.255.255.255`

- **Default Subnet Mask** of Class A - 255.0.0.0

- To identify whether an IP address belongs to Class A, perform a bitwise **AND operation** with the subnet mask (255.0.0.0). If the resulting value falls within the range for Class A (0 to 127 in the first octet), it’s a Class A IP address.

### Class B in IP Addressing

**Network ID** = 16 bits\
**Host ID** = 16 bits

![Class B Diagram](https://media.geeksforgeeks.org/wp-content/cdn-uploads/IP_addressing_5.jpg)

- IP addresses belonging to Class B range from **128.0.0.0** to **191.255.255.255**.

- Class B IP addresses are defined by the **first two bits of the first octet** being `10`. This means the first octet ranges from **128 to 191**.

- Class B IP addresses are identified by the **first two bits of the first octet**: `10`.

- **No. of IP Addresses** = 2^31

- **No. of Networks** = 2^14 = 16,384

- **No. of Hosts** = 2^16 - 2 = 65,534
  - Two addresses are reserved:
    1. **Network Address** (Reserved Host Address)
       - The **first address in the IP range** (i.e., `x.x.0.0` for any network in Class B) represents the **network address**.
       - This address identifies the network itself and **cannot be assigned to any device**. It helps routers and devices recognize the entire network, not any individual host.
       - Example: `128.0.0.0`.
    2. **Broadcast Address** (Reserved Host Address)
       - The **last address in the IP range** (i.e., `x.x.255.255` for any Class B network) is reserved as the **broadcast address**.
       - This address enables data to be sent to **all devices** on the network simultaneously.
       - Example: `128.255.255.255`.

- **Default Subnet Mask** of Class B - 255.255.0.0

- To determine if an IP address belongs to Class B, perform a bitwise **AND operation** with the subnet mask (255.255.0.0). If the result falls within the range for Class B (128 to 191 in the first octet), it is a Class B IP address.

### Class C in IP Addressing

**Network ID** = 24 bits\
**Host ID** = 8 bits

![Class C Diagram](https://media.geeksforgeeks.org/wp-content/cdn-uploads/IP_addressing_6.jpg)

- IP addresses belonging to Class C range from **192.0.0.0** to **223.255.255.255**.

- Class C IP addresses are defined by the **first three bits of the first octet** being `110`. This makes the first octet range **192 to 223**.

- Class C IP addresses are identified by the **first three bits of the first octet**: `110`.

- **No. of IP Addresses** = 2^29

- **No. of Networks** = 2^21 = 2,097,152

- **No. of Hosts** = 2^8 - 2 = 256 - 2 = 254
  - Two addresses are reserved:
    1. **Network Address** (Reserved Host Address)
       - The **first address in the IP range** (i.e., `x.x.x.0` for any network in Class C) is the **network address**.
       - This address identifies the network and **cannot be used by any device**.
       - Example: `192.0.0.0`.
    2. **Broadcast Address** (Reserved Host Address)
       - The **last address in the IP range** (i.e., `x.x.x.255` for any Class C network) serves as the **broadcast address**.
       - This address is used to communicate with **all devices** within the network.
       - Example: `192.0.0.255`.

- **Default Subnet Mask** of Class C - 255.255.255.0

- To check if an IP belongs to Class C, use a bitwise **AND operation** with the subnet mask (255.255.255.0). If the result is within the Class C range (192 to 223 in the first octet), it is a Class C IP address.

### Class D in IP Addressing

![Class D Diagram](https://media.geeksforgeeks.org/wp-content/cdn-uploads/IP_addressing_7.jpg)

- IP addresses belonging to Class D range from **224.0.0.0** to **239.255.255.255**.

- Class D IP addresses are defined by the **first four bits of the first octet** being `1110`. This means the first octet ranges **224 to 239**.

- **Class D is used exclusively for multicasting**. This means that data sent to a Class D address is distributed to multiple devices that are members of a multicast group.

- **No. of IP Addresses** = 2^28

- **Class D does not possess any subnet mask** because it is not intended for standard networking but for multicast groups.

- To identify Class D IPs, check if the first four bits are `1110`. The Class D range starts with 224 in the first octet.

---

### Class E in IP Addressing

![Class E Diagram](https://media.geeksforgeeks.org/wp-content/cdn-uploads/IP_addressing_8.jpg)

- IP addresses in Class E range from **240.0.0.0** to **255.255.255.255**.

- Class E IP addresses are defined by the **first four bits of the first octet** being `1111`. This restricts the first octet to **240 to 255**.

- **Class E addresses are reserved** for experimental and research purposes and are not used for standard networking.

- **No. of IP Addresses** = 2^28

- **Class E has no subnet mask** as it is reserved and not allocated for general use.

- To identify Class E, the first four bits should be `1111`, with the first octet ranging from 240 to 255.

### Disadvantages of Classful Addressing

Classful addressing, while foundational in the early stages of IP address management, presents several limitations. Here’s a breakdown of its main disadvantages:

1. **Less Flexible**\
   Classful addressing rigidly divides IP addresses into fixed classes (A, B, C, etc.), limiting address assignment based on class rather than actual network needs. This lack of flexibility can lead to inefficiency, as networks must fit into predefined classes rather than receiving a more tailored allocation.

2. **Wastage of IP Addresses**\
   The class-based system often leads to wasted addresses. For instance, a small network assigned a Class A address has access to millions of IP addresses but likely requires far fewer. Similarly, medium-sized networks may receive Class B addresses, with many addresses remaining unused. This rigid allocation led to rapid depletion of available IP addresses, even though many were not in use.

3. **Maintenance is Time-Consuming**\
   Network administrators must manage multiple classes of addresses with varying sizes and subnet masks, adding complexity to network planning and maintenance. As networks grow and change, this structure complicates the addition of new networks and sub-networks, requiring manual reconfiguration and redesign of addressing schemes.

4. **More Prone to Errors**\
   The rigid class structure, combined with varying subnet mask requirements and address ranges, increases the likelihood of errors in network configuration and assignment. Assigning incorrect addresses or subnet masks can lead to connectivity issues and miscommunication across the network, resulting in downtime and troubleshooting challenges.

These disadvantages ultimately led to the development of **Classless Inter-Domain Routing (CIDR)**, which provides a more efficient, flexible, and scalable solution for IP addressing by allowing variable-length subnet masking.
