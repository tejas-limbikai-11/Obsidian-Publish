# Selective Repeat ARQ Protocol

Selective Repeat Automatic Repeat Request (ARQ) is a reliable data transmission protocol within the sliding window protocols family. It allows only corrupted or lost frames to be resent, reducing bandwidth wastage.
![](https://images.javatpoint.com/tutorial/computer-network/images/sliding-window-protocol-4.png)

#### Key Characteristics

- **Window Size**: The sender and receiver windows can have a maximum size of (2^m - 1) (where `m` is the number of bits for sequence numbering). This limitation prevents ambiguity in frame identification.
- **Out-of-Order Frames**: Frames received out of order are accepted and buffered, allowing the receiver to store frames until the missing frame arrives and maintains continuity.
- **Error Handling:** When a receiver identifies a corrupted frame, it does not discard it. Instead, it sends a Negative Acknowledgment (NAK) to the sender, which prompts the immediate retransmission of only the affected frame.
- **Complexity and Storage Needs:** The Selective Repeat ARQ protocol is more complex than Go-Back-N due to additional requirements for sorting and searching. The protocol also necessitates more storage for buffering out-of-order frames until they can be correctly sequenced.

#### Advantages of Selective Repeat ARQ

1. **Efficiency**: Only specific frames are resent, leading to better bandwidth usage.
2. **Reduced Redundancy**: No need to resend correctly received frames.
3. **Error Resilience**: Works well even on high-error channels, as only problematic frames are resent.

#### Disadvantages of Selective Repeat ARQ

1. **Complexity**: Requires buffering, sorting, and searching, making it computationally heavier.
2. **Storage Requirements**: Needs additional memory to store out-of-order frames, increasing overall system complexity.

### Difference between the Go-Back-N ARQ and Selective Repeat ARQ?
