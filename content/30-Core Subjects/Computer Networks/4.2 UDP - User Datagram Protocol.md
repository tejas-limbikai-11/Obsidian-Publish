# User Datagram Protocol (UDP)

**User Datagram Protocol (UDP)** is a Transport Layer protocol. UDP is a part of the Internet Protocol suite, referred to as UDP/IP suite. Unlike TCP, it is an **unreliable and connectionless protocol.** So, there is no need to establish a connection before data transfer. The UDP helps to establish low-latency and loss-tolerating connections over the network. The UDP enables process-to-process communication.

## What is User Datagram Protocol?

User Datagram Protocol (UDP) is one of the core protocols of the Internet Protocol (IP) suite. It is a communication protocol used across the internet for time-sensitive transmissions such as video playback or [DNS lookups](https://www.geeksforgeeks.org/dns-look-up/) . Unlike Transmission Control Protocol (TCP), UDP is connectionless and does not guarantee delivery, order, or error checking, making it a lightweight and efficient option for certain types of data transmission.

**UDP** is a connectionless protocol that offers minimal error recovery services.

## UDP Header

UDP header is an **8-byte** fixed and simple header, while for TCP it may vary from 20 bytes to 60 bytes. The first 8 Bytes contain all necessary header information and the remaining part consists of data. UDP port number fields are each 16 bits long, therefore the range for port numbers is defined from 0 to 65535; port number 0 is reserved. Port numbers help to distinguish different user requests or processes.

![UDP-header](https://media.geeksforgeeks.org/wp-content/uploads/20240226104635/UDP-header.jpg)

UDP Header

- **Source Port:** Source Port is a 2 Byte long field used to identify the [port number](https://www.geeksforgeeks.org/what-is-ports-in-networking/) of the source.
- **Destination Port:** It is a 2 Byte long field, used to identify the port of the destined packet.
- **Length:** Length is the length of UDP including the header and the data. It is a 16-bits field.
- **Checksum:** Checksum is 2 Bytes long field. It is the 16-bit one’s complement of the one’s complement sum of the UDP header, the pseudo-header of information from the IP header, and the data, padded with zero octets at the end (if necessary) to make a multiple of two octets.

**Notes –** Unlike TCP, the Checksum calculation is not mandatory in UDP. No Error control or flow control is provided by UDP. Hence UDP depends on IP and ICMP for error reporting. Also UDP provides port numbers so that is can differentiate between users requests.

### Advantages of UDP

- **Speed:** UDP is faster than TCP because it does not have the overhead of establishing a connection and ensuring reliable data delivery.
- **Lower latency:** Since there is no connection establishment, there is lower latency and faster response time.
- **Simplicity:** UDP has a simpler protocol design than TCP, making it easier to implement and manage.
- **Broadcast support:** UDP supports broadcasting to multiple recipients, making it useful for applications such as video streaming and online gaming.
- **Smaller packet size:** UDP uses smaller packet sizes than TCP, which can reduce network congestion and improve overall network performance.
- User Datagram Protocol (UDP) is more efficient in terms of both latency and bandwidth.

### Disadvantages of UDP

- **No reliability:** UDP does not guarantee delivery of packets or order of delivery, which can lead to missing or duplicate data.
- **No congestion control:** UDP does not have congestion control, which means that it can send packets at a rate that can cause network congestion.
- **Vulnerable to attacks:** UDP is vulnerable to [denial-of-service attacks](https://www.geeksforgeeks.org/deniel-service-prevention/) , where an attacker can flood a network with UDP packets, overwhelming the network and causing it to crash.
- **Limited use cases:** UDP is not suitable for applications that require reliable data delivery, such as email or file transfers, and is better suited for applications that can tolerate some data loss, such as video streaming or online gaming.

### Applications of UDP

1. **Simple Request-Response Communication**: UDP is suitable for small data transmissions where speed is prioritized over reliability, as in quick request-response interactions with minimal error control and flow requirements.

2. **Multicasting**: UDP supports packet switching and is ideal for multicasting, making it effective for applications that need to send data to multiple receivers simultaneously.

3. **Routing Protocols**: Used by certain routing protocols like RIP (Routing Information Protocol), where updates are periodically broadcasted to maintain routing tables.

4. **Real-Time Applications**: UDP is commonly used in real-time applications like VoIP (e.g., Skype, WhatsApp) and online gaming, where low latency is essential. Here, timely delivery is prioritized over packet reliability to prevent delays.

5. **DNS (Domain Name System)**: UDP is used by DNS for sending query and response messages, as these are generally small, and UDP offers the quick response times DNS queries require.

6. **DHCP (Dynamic Host Configuration Protocol)**: UDP is utilized by DHCP to dynamically assign IP addresses to devices. UDP suits DHCP as it supports quick, small message exchanges without requiring high reliability.

7. **Time-Sensitive Applications**: Many time-sensitive applications and servers use UDP to respond to frequent, small queries from numerous clients without the overhead of connection establishment.

8. **Broadcast and Multicast Compatibility**: UDP allows packet broadcasts over a network, making it effective for both network-wide and targeted broadcasts, such as in media streaming and network discovery tasks.

### Comparison of TCP and UDP

| **Basis**           | **Transmission Control Protocol (TCP)**                                                                                                           | **User Datagram Protocol (UDP)**                                                                                                 |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| **Type of Service** | TCP is connection-oriented, meaning a connection must be established before data transfer and closed afterward.                                   | UDP is datagram-oriented, with no overhead for connection setup or termination, making it efficient for broadcast and multicast. |
| **Reliability**     | TCP is reliable, as it guarantees delivery of data to the destination.                                                                            | UDP does not guarantee delivery of data, making it less reliable.                                                                |
| **Error Checking**  | TCP provides extensive error-checking mechanisms, including flow control and acknowledgment.                                                      | UDP uses a basic error-checking mechanism (checksums) without advanced control.                                                  |
| **Acknowledgment**  | TCP includes acknowledgment segments for reliable data transfer.                                                                                  | UDP does not have acknowledgment segments.                                                                                       |
| **Sequence**        | TCP ensures sequencing of data, meaning packets arrive in order at the receiver.                                                                  | UDP has no sequencing; the application layer must manage ordering if required.                                                   |
| **Speed**           | TCP is slower than UDP due to its reliability and error-checking mechanisms.                                                                      | UDP is faster, simpler, and more efficient than TCP.                                                                             |
| **Retransmission**  | TCP supports retransmission of lost packets.                                                                                                      | UDP does not retransmit lost packets.                                                                                            |
| **Header Length**   | TCP has a variable-length header (20-60 bytes).                                                                                                   | UDP has a fixed-length header (8 bytes).                                                                                         |
| **Weight**          | TCP is considered heavy-weight due to its connection management.                                                                                  | UDP is lightweight, with minimal overhead.                                                                                       |
| **Handshaking**     | TCP uses handshakes (SYN, ACK, SYN-ACK) to establish connections.                                                                                 | UDP is connectionless, meaning there is no handshake process.                                                                    |
| **Broadcasting**    | TCP does not support broadcasting.                                                                                                                | UDP supports broadcasting, useful for applications needing data distribution to multiple recipients.                             |
| **Protocols**       | Common TCP-based protocols include HTTP, HTTPS, FTP, SMTP, and Telnet.                                                                            | Common UDP-based protocols include DNS, DHCP, TFTP, SNMP, RIP, and VoIP.                                                         |
| **Stream Type**     | TCP operates as a byte stream, maintaining the flow of data bytes.                                                                                | UDP operates as a message stream, sending discrete packets independently.                                                        |
| **Overhead**        | TCP has relatively low overhead but higher than UDP due to connection management.                                                                 | UDP has very low overhead, focusing on minimal data transfer requirements.                                                       |
| **Applications**    | TCP is used in applications requiring reliable communication, such as email, web browsing, and secure transactions (e.g., military applications). | UDP is used where speed is prioritized over reliability, such as in VoIP, online gaming, and video or audio streaming.           |
