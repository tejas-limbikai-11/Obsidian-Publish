# Transmission Control Protocol (TCP)

## Transmission Control Protocol (TCP)

**Transmission Control Protocol (TCP)** is one of the core protocols in the TCP/IP suite, designed to enable reliable and orderly data transmission between devices over a network. TCP is widely used in applications where data integrity and accuracy are essential, such as web browsing, file downloads, and email.

#### Key Characteristics of TCP:

##### 1. **Reliability**:

TCP ensures that data sent from one computer is received accurately and in the correct order on the other end. This reliability is essential when viewing web pages or downloading files, as it guarantees that all parts of the data, including text and images, are complete and correctly arranged.

##### 2. **Connection-Oriented Protocol**:

- TCP is connection-oriented, meaning it establishes a connection before data transfer and terminates the connection once data transmission is complete.
- **Three-Way Handshake**: To initiate a connection, TCP uses a three-step process: ^wan7u0
  - The sender transmits a **SYN** (synchronize) message to initiate the connection.
  - The receiver responds with a **SYN-ACK** (synchronize-acknowledge) message to confirm receipt.
  - The sender completes the handshake by sending an **ACK** (acknowledge) message back to the receiver.
    ![500](00-Attachments/4.1 TCP - Transmission Control Protocol.gif)
    - After the handshake, the connection is established, allowing reliable data exchange.

##### 3. **Features of TCP**:

- **Data Delivery**: TCP guarantees in-order, complete data delivery. If any data is missing or received incorrectly, TCP will retransmit the missing segments.
- **Full Duplex:** In TCP data can be transmitted from receiver to the sender or vice – versa at the same time.
- **Connection Oriented:** It means sender and receiver are connected to each other till the completion of the process. The order of the data is maintained i.e. order remains same before and after transmission.
- **Error Checking and Correction**: TCP includes mechanisms to detect errors in transmitted data, ensuring that only accurate data is delivered to the recipient.
- **Flow Control**: TCP manages data flow between sender and receiver, preventing the receiver from being overwhelmed by data it cannot process.
- **Congestion Control**: TCP adapts to network conditions to prevent congestion, dynamically adjusting the data transmission rate.

#### How TCP Works:

- **Data Transmission**: Once a TCP connection is established, data is segmented, sequenced, and then transmitted. Each segment carries a sequence number to ensure data arrives in order, and acknowledgments (ACKs) are sent for received data.
- **Connection Termination**: When data transmission is complete, TCP closes the connection to free network resources. This process ensures an orderly end to the session, preventing lingering connections and freeing system resources.

### Advantages of TCP

1. **Reliability**: TCP is known for its reliability, ensuring data integrity through its error-checking and retransmission mechanisms.
2. **Error Detection and Recovery**: Includes built-in error-checking and recovery features, allowing it to detect lost or corrupted packets and automatically request retransmission.
3. **Flow Control**: Implements flow control techniques to prevent data overload and manage the data rate between sender and receiver effectively.
4. **Ordered Data Delivery**: Ensures that data arrives at the destination in the exact order it was sent, making it suitable for applications requiring in-sequence data, such as file transfers.
5. **Standards and Documentation**: Widely documented and maintained by standards organizations like the Internet Engineering Task Force (IETF), ensuring broad compatibility and stability.
6. **Integration with IP**: Works with the Internet Protocol (IP) to establish network connections, making it foundational to the TCP/IP suite.

### Disadvantages of TCP

1. **Resource Intensive**: Designed primarily for wide-area networks, TCP’s extensive error-handling and flow-control mechanisms may be resource-intensive for small networks with limited resources.
2. **Latency**: Due to its multiple layers of error-checking and data verification, TCP can introduce latency, potentially slowing down the network in applications where speed is prioritized over reliability.
3. **Lack of Flexibility**: TCP is specific to the TCP/IP protocol suite, limiting its interoperability with other network protocols, such as those used in Bluetooth or other proprietary stacks.
4. **Outdated Aspects**: TCP has remained largely unchanged since its development over 30 years ago, leading to some limitations in adapting to modern network demands and applications requiring more flexibility.

### Applications of TCP

1. **Cross-Platform Connectivity**: TCP allows connections to be established between different types of computers, regardless of their hardware or operating systems.
2. **Operating System Independence**: TCP functions independently of the operating system, making it widely compatible across platforms.
3. **Supports Multiple Routing Protocols**: TCP works with various routing protocols, enhancing its versatility and enabling efficient routing of data.
4. **Facilitates Internetworking**: TCP enables internetworking between organizations, allowing different networks to communicate and share data securely.
5. **Connection Establishment**: TCP is widely used to establish stable, reliable connections between two computers, supporting applications like web browsing, file transfers, and email.
6. **Independent Operation**: TCP operates independently, meaning it can function across different network types without relying on specific hardware or software configurations, making it highly adaptable to various network environments.

### TCP Segment Structure

A TCP segment consists of a data section and a header. The header ranges from 20 to 60 bytes, with 20 bytes being the minimum size (no options) and up to 60 bytes if options are included.

![500](00-Attachments/4.1 TCP - Transmission Control Protocol.png)

#### Header Fields:

1. **Source Port (16-bit)**: Port number of the application sending the data.

2. **Destination Port (16-bit)**: Port number of the application receiving the data.

3. **Sequence Number (32-bit)**: Byte number of the first byte sent in this segment, used to reassemble segments in the correct order.

4. **Acknowledgment Number (32-bit)**: Byte number of the next expected byte, acknowledging receipt of previous bytes.

5. **Header Length (HLEN, 4-bit)**: Indicates header size in 4-byte words. Values range from 5 (20 bytes) to 15 (60 bytes).

6. **Control Flags (6 bits)**:

   - **URG**: Urgent pointer valid.
   - **ACK**: Acknowledgment number valid.
   - **PSH**: Request to push data to application immediately.
   - **RST**: Reset the connection.
   - **SYN**: Synchronize sequence numbers for connection establishment.
   - **FIN**: Terminate the connection.

7. **Window Size**: Specifies the window size in bytes, indicating the amount of data the receiver can accept.

8. **Checksum**: Provides error-checking for segment integrity (mandatory in TCP).

9. **Urgent Pointer**: Points to urgent data within the segment (only valid if the URG flag is set).
