# Go-Back-N ARQ Protocol

The Go-Back-N (GBN) protocol is a [data link layer](2.%20Data%20Link%20Layer.md) protocol used in networking for reliable communication. It is a type of automatic repeat request (ARQ) protocol that uses **sliding window techniques**. The key concept of GBN is that it allows the sender to send several frames before needing an acknowledgment for the first one, up to a specified window size.

![](https://images.javatpoint.com/tutorial/computer-network/images/sliding-window-protocol-2.png)

### Key Concepts

1. **Sliding Window Protocol**: In GBN, both the sender and receiver maintain a window of frames. The sender can send frames within this window without waiting for an acknowledgment for each individual frame. The receiver, however, can only accept frames in order and must discard any out-of-order frames.

2. **Window Size**: The window size `N` defines how many frames can be sent before requiring an acknowledgment. This window size must be less than `2 ^ m - 1`, where `m` is the number of bits used for the sequence numbers.

3. **Sequence Numbers**: Each frame is assigned a unique sequence number to identify it. The sequence number is used by the receiver to determine the order of frames and to identify which frames need to be acknowledged.

4. **Acknowledgments (ACKs)**: The receiver sends back an acknowledgment for the highest-numbered frame it has received in order. If a frame is lost or received out of order, the receiver will discard it and all subsequent frames until the lost frame is retransmitted.

5. **Out-of-Order Packets**: If the sender transmits frames in sequence, but a frame is lost or corrupted (e.g., frame 2), and the receiver gets frame 3, it cannot acknowledge frame 3 because it hasn't received frame 2. Consequently, the receiver will discard frame 3, leading to inefficiencies. This mechanism emphasizes the necessity of in-order delivery, as GBN only operates effectively when frames are processed sequentially.

### Important Points

1. **Window Size Limit**:
   - The maximum window size is `N < 2^m` to ensure that the sequence numbers can be uniquely identified.
   - If the window size equals `2^m`, it can lead to erroneous acceptance of frames because the sequence numbers will wrap around, and the receiver may mistakenly consider a frame with a sequence number that has wrapped around as a valid frame when it is not.

2. **Error Handling**:
   - If a frame is lost or corrupted, the receiver does not acknowledge it. The sender will time out after a specified period and will retransmit that frame and all subsequent frames, hence the name "Go-Back-N".
   - This can lead to inefficiencies, especially in networks with high error rates, as many frames may need to be retransmitted.

### Example Scenario

1. **Window Size of 3**: Suppose the sender has a window size of 3 and has sent frames with sequence numbers 0, 1, and 2.
   - If the receiver receives frames 0 and 1 and discards frame 2 (due to an error), it will send an acknowledgment for frame 1.
   - The sender then knows to retransmit frame 2 and any frames sent after it (if any), leading to sending frames 2, 3, and 4 again.

### Advantages and Disadvantages

#### Advantages

- Efficient use of the bandwidth compared to [Stop-and-Wait ARQ](2.2.1%20Stop%20and%20Wait%20Protocol.md) because multiple frames can be sent without waiting for an acknowledgment for each one.
- Simple implementation and low overhead.

#### Disadvantages

- Can lead to a significant number of retransmissions in case of errors, particularly in environments with high packet loss.
- Requires more memory to maintain the sliding window and sequence numbers.
- Out-of-order packets must be handled carefully, as they lead to frame discards and additional retransmissions, which can reduce overall efficiency.

### Conclusion

The Go-Back-N protocol is a straightforward yet powerful method for managing reliable communication in networking. It maximizes efficiency by allowing multiple frames to be sent before needing an acknowledgment, but it must adhere to the constraints of window size to avoid complications with sequence number wrapping. Understanding the mechanics of GBN, including how it deals with out-of-order packets, is crucial for designing effective communication protocols in computer networks.
