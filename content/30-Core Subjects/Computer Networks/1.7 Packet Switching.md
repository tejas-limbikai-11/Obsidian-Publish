# Packet Switching

Packet switching is a method used in network communications where data is broken down into smaller packets before being transmitted. Each packet is routed independently based on the network conditions, which allows for efficient and reliable data transfer.

### Types of Packet Switching

1. **[1.8 Datagram vs Virtual Circuit in Packet Switching](1.8%20Datagram%20vs%20Virtual%20Circuit%20in%20Packet%20Switching.md#Datagram%20Switching|Datagram%20Packet%20Switching)**
   - Operates at the **[Network Layer](3.%20Network%20Layer.md)**.
   - Packets, called datagrams, are treated independently, with each packet finding its own route through the network.

2. **[1.8 Datagram vs Virtual Circuit in Packet Switching](1.8%20Datagram%20vs%20Virtual%20Circuit%20in%20Packet%20Switching.md#Virtual%20Circuit|Virtual%20Circuit%20Packet%20Switching)**
   - Operates at the **[Data Link Layer](2.%20Data%20Link%20Layer.md)**.
   - Establishes a virtual path before transmitting data, ensuring packets follow the same route for the entire session.

### Key Characteristics of Packet Switching

- **[Data Link Layer](2.%20Data%20Link%20Layer.md) and Network Layer Support:** Operates primarily at the data link and network layers of the OSI model.
- **Store and Forward Mechanism:** Each node stores the entire packet before forwarding it to the next node.
- **Pipelining:** Increases efficiency as packets are sent in a sequence, reducing transmission time.
- **Efficiency:** Maximizes bandwidth usage by sending packets individually through available paths, reducing wait time.
- **Delay Variability:** Due to the independent routing of packets, delays can vary based on network congestion.

Detailed note expanding on each key point:

### 1. Data Link and Network Layer

- **[Data Link Layer](2.%20Data%20Link%20Layer.md)**: Provides reliable data transfer across a physical network link by handling error detection, flow control, and framing. It establishes a direct node-to-node transfer of data.
- **Network Layer**: Primarily responsible for determining the best route for data packets based on network conditions and availability. It performs logical addressing, routing, and forwarding.
- Together, these layers ensure that packets can move efficiently from the source to the destination across multiple hops.

### 2. Store and Forward

- In packet-switched networks, each packet is temporarily stored in a buffer at each node before being forwarded to the next hop.
- This **Store and Forward** mechanism allows nodes to check for errors, queue packets if there’s congestion, and retransmit when necessary.
- This approach increases reliability, as each packet's integrity is verified before it continues along its path.

### 3. Pipelining

- **Pipelining** in packet switching means that multiple packets can be sent in sequence without waiting for previous packets to reach the destination.
- Each packet is processed and forwarded independently, allowing the network to handle multiple packets simultaneously.
- This increases the overall speed of data transmission, as different nodes can process and forward packets concurrently, minimizing idle time.

### 4. Efficiency

- Packet switching utilizes bandwidth more efficiently than circuit switching since packets are transmitted over the most available paths instead of reserving a single path.
- In a shared network, packets from multiple sources can travel across the same lines, maximizing **network utilization** and reducing transmission costs.
- The flexibility to use various routes improves resilience and allows the network to accommodate high traffic and varying loads.

### 5. Delay

- Unlike circuit-switched networks, where a dedicated path ensures constant transmission delay, packet-switched networks experience **variable delays**.
- Delays can result from:
  - **Routing decisions** where packets may take different paths based on network load.
  - **Network congestion** where packets wait in queues at nodes.
  - **Processing time** at each node to store, forward, and check for errors.
- While packet switching does introduce variability, the trade-off is better bandwidth utilization and fault tolerance.

Packet switching, through its efficient use of bandwidth and independent routing of packets, forms the backbone of modern internet communication, contrasting with circuit switching, which is more commonly associated with traditional voice communications.

## Difference Between Packet Switching and Circuit Switching

| **Comparison Basis**            | _**Packet Switching**_                                                           | _**Circuit Switching**_                                                       |
| ------------------------------- | -------------------------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| **Data Transmission**           | Data is divided into packets, each sent independently.                           | A dedicated path is established for the entire data transmission.             |
| **Processing of Data**          | Data is processed at all intermediate nodes, including the source system.        | Data is processed only at the source system.                                  |
| **Delay**                       | Delay between data units is not uniform.                                         | Delay between data units is uniform.                                          |
| **Reliability**                 | Generally less reliable due to possible packet loss or reordering.               | More reliable, as a dedicated path ensures consistent delivery.               |
| **Transmission Responsibility** | Data transmission is managed by both the source and intermediate routers.        | Transmission is managed solely by the source system.                          |
| **Resource Utilization**        | Less resource wastage, as packets use shared network resources dynamically.      | Higher resource wastage, as resources are reserved for the entire connection. |
| **Physical Path**               | No dedicated physical path between source and destination.                       | A dedicated physical path exists between source and destination.              |
| **Call Setup**                  | Call setup is not required; data can be sent at any time.                        | Call setup is required before data transmission can begin.                    |
| **Protocol Complexity**         | Requires complex protocols to manage packet routing and sequencing.              | Uses simpler protocols for managing data transmission.                        |
| **Latency**                     | Generally higher latency due to routing and processing at each node.             | Lower latency, as data follows a single, established path.                    |
| **Overhead**                    | Slightly higher overhead due to additional control information with each packet. | Lower overhead, as data follows a single established path.                    |
